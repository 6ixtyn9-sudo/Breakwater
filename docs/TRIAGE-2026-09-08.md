## 1. THE FIRE — the green gate oscillates, and every flip liquidates the book

`lane_gate.py` decides a lane is red when `closed >= 10 and cumulative_pnl <= 0`.
Cumulative PnL is a random walk. A threshold sitting exactly at zero on a random walk

**Four state flips in six days.** Each GREEN window opens every slice in the book at once
(`families_considered 38 / families_promoted 38`); each subsequent FROZEN window
force-liquidates every position that is not a proven green island.

- **32 of 72 real closes (44%) were forced `lane_gate` exits**, not stop/target/horizon.
- Liquidation events: 5 positions on 09-03, 5 on 09-05, 3 on 09-05, **9 on 09-06**,
  **7 on 09-07** (that one booked **−23.04 ZAR** in a single cycle).

**Measured cost of the forced liquidations.** The ghost control

**31 trades whose actual exit was `lane_gate`**, the control would have scored

That +141 ZAR is the single largest P&L line in the entire log, and it is entirely

## 3. THE DISEASE — the estimator, not the market

This is the answer to "past validated slices cannot predict the future."

Breakwater scores a `(feature, state, side, horizon)` cell by its **in-sample mean**, then
promotes the winners. The significance test behind it is a plain t-test
(`discovery._stat_block`: `mean / (std / sqrt(n))`) with **Bonferroni OFF**
(`BREAKWATER_VALIDATION_REQUIRE_BONFERRONI=0`).

Two runs, same feature library, same venue, opposite conclusions:

| | Production research | Deep-history audit (§21) |
|---|---|---|
| Candles | 1,000 | 5,000 |
| Horizons | 1–24 | 1–48 |
| Candidates (native) | 3,744 | 3,744 |
| Error model | naive t-test, rows independent | 48h block bootstrap |
| Multiple testing | Bonferroni **off**, 2 fold passes | plateau ≥ 3 contiguous horizons |
| Validated / passing | **779 (20.8%)** | **0** |
| Best reported p | **0.0000** | **0.3854** |

The audit has been run. It is committed at `localdata/deep_audit/candidates.csv`
(18,720 rows). It found nothing, and nobody read it — it is manual, non-promoting, and
the daily digest that would have surfaced it died on 03 Sep (§5).

**Why the gap.** A 1,000-hour window contains **≈20 independent 48-hour blocks**. The
t-test is handed n ≈ 14,711 and reports p = 0.0000. The pooled rows are overlapping
24-bar windows sampled every bar, across 40–110 crypto symbols that all carry the same
BTC beta. Independent information is overstated by roughly **three orders of magnitude**.

**Where the screen actually binds** (native, 3,744 candidates):

```
weighted_5000_mean > 0          231 / 3744   (  6.2%)
full_5000_mean     > -0.001     139 / 3744   (  3.7%)
positive_symbol_fraction >= 0.40  24 / 3744   (  0.6%)
reached the bootstrap            17 / 3744
best block_bootstrap_p          0.3854   (threshold 0.20)
```

**94% of candidates have a negative weighted mean**, and the best candidate is positive in
at most **49% of symbols** — a coin flip. These are not market states. They are
minority-of-names artifacts riding a search over 3,744 cells.

Two further notes:
- The strongest raw means in the audit sit at **h44–48** (`feat_ret_20:2:LONG`,
  `feat_trend_strength_20:2:LONG`) — **outside the production h1–24 search window**.
  Production may be looking in the wrong band.
- `cluster_count` is 0 for all but 17 rows: the ≥0.80 correlation clustering collapses
  55 crypto names into ~50 clusters, i.e. almost no independent breadth exists to confirm
  anything. That is the honest answer, and it is a property of the universe, not a bug.
